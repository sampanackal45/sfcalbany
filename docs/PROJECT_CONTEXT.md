# PROJECT_CONTEXT.md

## Project Overview

This project is a full redesign and rebuild of the **Sharon Fellowship Church of Albany** website.

The current website is built with WordPress, but the new version should be custom-coded using a modern frontend stack. The goal is to keep the church’s existing content and message while completely upgrading the design, layout, user experience, performance, accessibility, SEO, and code quality.

The website should feel modern, clean, trustworthy, and welcoming while still looking unique and visually impressive. This is a church website, so the design should feel spiritual, warm, and community-focused, not corporate or overly flashy.

The code should be production-quality, secure, maintainable, responsive, and easy to update later.

## Security Requirements

The code should be written with security in mind.

Important security rules:

- Do not expose API keys
- Do not hardcode secrets
- Do not use unsafe HTML injection
- Avoid `dangerouslySetInnerHTML` unless absolutely necessary
- Validate and sanitize user-controlled inputs
- Use safe external links
- External links should use `rel="noopener noreferrer"` when opening in a new tab
- Do not add unnecessary third-party scripts
- Do not use outdated or suspicious packages
- Do not include tracking scripts unless specifically requested
- Do not include fake form handling that pretends to send messages
- Keep dependencies minimal and reputable
- Avoid code patterns that create XSS risks
- Avoid storing sensitive data in the frontend

If a contact form is added, it should be coded safely and should not expose private credentials.

---

## Accessibility Requirements

The website should be accessible and easy to use.

Accessibility requirements:

- Use semantic HTML
- Use proper heading order
- Add alt text to images
- Ensure strong color contrast
- Make buttons and links keyboard accessible
- Use visible focus states
- Avoid tiny text
- Avoid low-contrast text
- Do not rely only on color to communicate meaning
- Respect reduced motion preferences where possible
- Make mobile navigation accessible
- Use descriptive aria labels only when needed
- Do not overuse ARIA when semantic HTML is enough

The site should feel polished for all users, including users on mobile devices and users using assistive technology.
